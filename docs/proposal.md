# 企画書 — asoviba（アソビバ）

> 便利ツールを気軽に“遊べる”Webツール集

- ドキュメント種別: 企画書（Proposal）
- 最終更新: 2026-10-12
- ステータス: Draft v0.1

---

## 1. プロダクト概要

**asoviba（遊び場）** は、開発・日常の「ちょっとした作業」をブラウザ上で完結できる便利ツールを多数集めたWebアプリケーション。
ユーザーは会員登録なしで、必要なツールにすぐアクセスして使える。「このサイトに来ればだいたい揃っている」状態を目指す。

- **コンセプト**: 軽い・速い・すぐ使える・安全（データを外に出さない）
- **名前の由来**: 「遊び場（あそびば）」＝気軽に立ち寄って色々なツールで遊べる場所

## 2. 背景・課題

- 単機能ツールサイトは無数にあるが、広告過多・重い・UIがバラバラ・信頼性不明なものが多い。
- 「JSON整形したいだけ」「Base64したいだけ」のたびに別サイトを探すのは非効率。
- ツールにデータを貼り付ける際、そのデータが外部送信されていないか不安（プライバシー）。

## 3. 提供価値（Value Proposition）

| 価値 | 内容 |
|---|---|
| **一箇所に集約** | 複数ジャンルの定番ツールを統一UIで提供 |
| **高速** | 静的配信＋クライアント処理中心で待たせない |
| **プライバシー安全** | 原則データはブラウザ内で処理、外部送信しない旨を明記 |
| **使いやすさ** | 統一されたUI、検索、ダークモード、キーボード操作 |

## 4. ターゲットユーザー

- **公開範囲**: 一般公開（不特定多数・ログイン不要）
- **主な利用者像**:
  - エンジニア／Web制作者（開発者系ユーティリティ）
  - ブロガー・ライター・学生（テキスト変換系）
  - 一般ユーザー（画像・日常・計算系）
- 検索流入（SEO）を主要な集客チャネルとして想定。

## 5. 提供する主なツールジャンル

1. **開発者系ユーティリティ**: JSON整形/検証、Base64、URLエンコード、正規表現テスト、UUID生成、diff、ハッシュ生成 など
2. **テキスト・変換系**: 文字数カウント、ケース変換、Markdownプレビュー、文字コード変換、全角/半角変換 など
3. **画像・メディア系**: 画像圧縮、リサイズ、フォーマット変換、QRコード生成 など
4. **日常・計算系**: 単位変換、日付計算、割り勘、タイマー、パスワード生成 など

> 初期は各ジャンルから「定番」を少数リリースし、アジャイルに拡充する（詳細はロードマップ参照）。

## 6. 収益モデル

- **主軸: Google AdSense**（ディスプレイ広告）
  - 一般公開・検索流入前提なので広告との相性が良い。
  - UXを損なわない範囲で広告枠を配置（ツール操作の邪魔をしない方針）。
- 将来的な選択肢（未確定）: アフィリエイト、プレミアム（広告非表示）、API提供。

### 収益化の技術的前提（調査済み）

- **AdSense はホスティング先を問わない**。Cloudflare 上でも問題なく審査・配信が可能。
- 留意点は2つ（いずれも設定で回避可能、仕様書で対応）:
  1. `ads.txt` が Cloudflare のBot対策でクロール拒否されうる → ルート配信＋チャレンジ除外で対応。
  2. クライアント描画のみだと審査でコンテンツが読まれにくい → 各ツールページを静的HTML（SSG）で生成し回避。

## 7. 成功指標（KPI 案）

- **初期（審査通過まで）**: AdSense 審査合格、主要ツール 6〜10 個稼働、Lighthouse 90+。
- **グロース期**: 月間アクティブユーザー、ツール別利用数、検索流入数、平均表示速度（LCP）、広告収益。
- **定性**: 「また使いたい」と思えるUX（リピート率）。

## 8. スコープ外（Non-Goals / 現時点）

- ユーザー登録・ログイン・個人データ保存（将来検討）。
- モバイルネイティブアプリ（まずはレスポンシブWebで対応）。
- 大規模なサーバーサイド計算基盤（必要なツールのみ個別にサーバー処理）。

## 9. リスクと対応方針

| リスク | 対応 |
|---|---|
| AdSense審査に落ちる | 初期から十分なコンテンツ量・プライバシーポリシー・明確なナビゲーションを用意 |
| 類似ツールサイトとの差別化 | 統一UX・速度・プライバシー安全性を訴求 |
| Astro 未経験による立ち上がりコスト | 仕様書に学習ポイントを明記、Phase 0でパターンを確立し以降は踏襲 |
| ツール増加による保守性低下 | ツールを機能単位で独立させ、メタデータ駆動で登録（仕様書参照） |
